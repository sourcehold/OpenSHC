# Synchronization hash validation

`compute_hash.py` compares the actual compiled `DirectionAlgorithmState::computeHash`
with the original x86 function, in an emulator. It does not run or modify the game.
No original game bytes or executable are distributed here.

The routine adds each complete little-endian 32-bit word to an unsigned accumulator,
then rotates the accumulator left by one bit. It ignores the final one to three
bytes, returns zero for signed lengths below four, and does not use `this` or RNG.
The native function unrolls blocks of sixteen words. The implementation uses
MSVC inline assembly, following the existing IO/DecoderState codec pattern, to
preserve those blocks, the tail loop and register/stack behavior. Compiling with
MSVC 2005 SP1 `/O2` produces an exact match for all 181 bytes in both variants.
The checker requires that byte match in addition to the independent behavior tests.

The corresponding high-level operation is:

```cpp
uint hash = 0;
while (byteCount >= 4) {
    hash += static_cast<uint>(*address++);
    hash = (hash << 1) | (hash >> 31);
    byteCount -= 4;
}
return hash;
```

The initial PR used this compact loop directly, which passed behavior checks but
produced very different code (33 bytes and a reported reccmp score of 0%). The
current version preserves the native structure instead. The checker compares
the compiled function's relocation-free object section. A separate isolated
RelWithDebInfo `OpenSHC.dll` build also reports **100% reccmp matching** for
`0x46CD30`; this does not certify the rest of the DLL or live gameplay.

For that linked comparison, select this source in
`cmake/openshc-sources.txt.local`, build the `OpenSHC.dll` target, and from
`reccmp/dll` run `reccmp-reccmp --target STRONGHOLDCRUSADER --verbose 0x46cd30`.
The local comparison used reccmp 0.1.6 and temporarily appended `/MANIFEST:NO`
to the shared RelWithDebInfo linker flags to avoid the legacy manifest-tool
failure previously encountered in this environment. That build-only change is
not part of the PR. Unselected source files can produce missing-symbol warnings;
the selected hash routine matched. No deploy target was run.

From a checkout with the project's MSVC 2005 SP1 toolchain and dependencies, compile
the actual source with the normal project headers. These PowerShell commands use
only an object output in `tmp`; they do not link, install a DLL, or change resolvers:

```powershell
$taskRoot = (Get-Location).Path
$taskMsvc = Join-Path $taskRoot 'MSVC1400-SP1'
$env:PATH = "$taskMsvc/Common7/IDE;$taskMsvc/VC/bin;$env:PATH"
$env:INCLUDE = "$taskMsvc/VC/include;$taskMsvc/VC/PlatformSDK/Include"
New-Item -ItemType Directory -Force tmp | Out-Null
& "$taskMsvc/VC/bin/cl.exe" /nologo /c /O2 /EHsc /DOPEN_SHC_DLL `
    /I "$taskRoot/src" /I "$taskRoot/dependencies/ucp3/include" `
    /I "$taskRoot/dependencies/lua/include" /FI "$taskRoot/src/precomp/pch.h" `
    /Fotmp/computeHash.obj src/OpenSHC/Map/Navigation/DirectionAlgorithmState/computeHash.cpp
if ($LASTEXITCODE -ne 0) { throw 'Compilation failed' }
python -m pip install pefile unicorn==2.1.4
python tools/reimplementation-tests/compute_hash.py tmp/computeHash.obj 'PATH/Stronghold Crusader.exe'
python tools/reimplementation-tests/compute_hash.py tmp/computeHash.obj 'PATH/Stronghold_Crusader_Extreme.exe' --address 0x46cf50
```

Use Python 3.10 or later without `-O` (the checker uses assertions). The input
object must contain the self-contained x86 function section generated by `/O2`.
The test checks 980 cases per executable: negative/zero lengths, every length up
to 131, larger block boundaries, overflow-heavy data, and seeded random buffers.
It also checks input read bounds, absence of non-stack writes, preservation of
callee-saved registers, and `thiscall` stack cleanup.

Validated executables:

| Game | Function address | Executable SHA256 |
| --- | --- | --- |
| Crusader 1.41 | `0x0046CD30` | `3bb0a8c1e72331b3a30a5aa93ed94beca0081b476b04c1960e26d5b45387ac5a` |
| Extreme 1.41 | `0x0046CF50` | `55648e6b05d67d37a5773fe699bbb17a2d6ad4de1bb9dbded9a21caef82bd7fb` |

These checks validate this hash routine only. Hashing entire unit structures is
not sufficient evidence of replay determinism: those structures also contain
presentation and local selection fields. This implementation does not enable
multiplayer playback or establish a canonical whole-world state fingerprint.
